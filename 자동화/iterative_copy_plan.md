# Iterative Copy Plan

이 문서는 `원본 [카피, 미디어] -> 변형 카피`를 단계적으로 확장하는 2번 아이디어의 계획만 정리한 문서입니다.
현재 코드는 구현하지 않았습니다.

## 목표

- 원본이 약할 때만 추가 생성으로 변형 폭을 넓힌다.
- 같은 게시글 자산(로컬 미디어, 쿠팡 정보, 상품 이미지)을 재사용해서 속도를 유지한다.
- 실패 시에도 캐시된 자산만으로 후속 생성을 빠르게 재개할 수 있게 한다.

## 전제

- 원본 순위 `5위 이내`면 strong original로 저장한다.
- 이 문서는 `입력이 두 개면 망가질 수 있다`는 우려를 반영해, 멀티 입력 반복 대신 `단계별 단일 카피 입력`을 기본 전제로 둔다.

## 제안 흐름

1. 기본 실행
- 입력: `A(원본 카피), 1(원본/로컬 미디어)`
- 출력: `A'1`

2. 2차 실행
- 입력: `A'1, 1`
- 출력: `A'2`

3. 3차 실행
- 입력: `A'2, 1`
- 출력: `A'3`

## 게이트

- `원본 rank <= 5`: 추가 반복 생성 없이 strong original로 저장
- `원본 rank > 5`: 반복 생성 후보군 진입
- 반복 단계마다 아래 중 하나라도 걸리면 중단
- 이전 단계와 텍스트 유사도가 너무 높음
- 상품 정보/소구점이 손상됨
- 회귀 점수 또는 토너먼트 결과가 개선되지 않음

## 구현 시 필요한 체크

- 단계별 결과를 `variants.json`에 누적
- 각 단계의 입력/출력/점수/유사도 로그 저장
- 최대 반복 횟수 제한
- 최종 게시용 후보는 계정 수만큼만 선별

## 보류 이유

- 현재는 실패 복구용 캐시와 strong original 축적이 우선순위가 더 높음
- 반복 생성은 입력 설계가 잘못되면 원본 맥락이 빠르게 붕괴할 가능성이 있어 별도 검증이 필요함
